# 04 · 实拍测试清单

第一阶段软件完成后，按下面的顺序验证。每一项都给出**通过标准**，
不通过时先查对应原因，再进入下一项。

---

## 0. 台架测试（不装摄像机）

| # | 动作 | 通过标准 |
|---|---|---|
| 0.1 | 运行 `--sim --autostart`，跑 `pose_monitor.py` | Free-D / JSON 约 500 Hz，校验失败 0 |
| 0.2 | UE 添加 LiveLinkFreeD Source:40000 | Subject `Camera 0` 出现并持续刷新 |
| 0.3 | CineCamera + LiveLinkController | 虚拟相机跟随模拟轨迹运动 |
| 0.4 | 点「重置原点」 | 位置/航向归零，虚拟相机停在原点朝向 |

台架不过，不要上实拍。

## 1. 静态漂移

DS80 固定，摄像机不动，静置 **10 分钟**。

- 记录开始/结束的位置（Bridge 的 X/Y/Z）与置信度。
- 通过标准：位置漂移 < 1–2 cm（Mix 模式）；若明显更大，改用 CSLAM 建图。
- 同时观察置信度是否周期性掉到 0（暗光/低纹理会导致）。

---

## 2. 基本六自由度方向

按 [02-UE5-FreeD集成](02-UE5-FreeD集成.md) 第 4 节的六项逐一核对。
通过标准：六个方向全部一致，无需（或仅需少量）反向校正。

---

## 3. 推拉摇移回原点

| 动作 | 通过标准 |
|---|---|
| 向前推 1m，再退回起点 | 回到起点时 X/Y/Z 误差 < 1cm |
| 向右横移 1m 再退回 | 同上 |
| 摇摄 90° 再回正 | 航向误差 < 0.2° |
| 俯仰 ±30° 再回正 | 俯仰误差 < 0.2° |
| 绕场地走一圈回起点 | 位置误差 < 2cm（闭环） |

误差用 Bridge 的读数记录，不要只看 UE 画面。

---

## 4. 遮挡与恢复

| 动作 | 观察 | 通过标准 |
|---|---|---|
| 用手完全挡住双目 3 秒 | 置信度 → 0；Bridge 状态变「数据中断」 | UE 相机保持最后位置，不瞬移 |
| 移开手 | 置信度恢复 | 画面在 1 秒内恢复跟踪 |
| 挡住后移动 1m 再移开 | 重定位 | 位置跳变 < 5cm；若跳变大，记录并反馈 |
| 快速甩镜头 | 运动模糊 | 不丢失；若丢失，降低运动速度或改善光照 |

> Free-D 没有“丢失”标志，UE 端只能保持最后一帧。Bridge 的 JSON 里有 `valid`/`conf`，
> 第二阶段的插件会用它做“冻结/淡出”处理。

---

## 5. 长距离与地图复用（CSLAM）

- 沿实际拍摄路线走 5–10 分钟，记录总里程与终点误差。
- 通过标准：误差 < 里程的 1%（例如 50m 走回起点误差 < 0.5m）。
- 若要多次拍摄同一场景：先用 CSLAM 建图并保存，之后加载地图，
  保证每次开机坐标系一致（这是 Free-D + IMU 单独做不到的）。

当前 Bridge **尚未接入 CSLAM 的保存/加载 API**，这是第二阶段的优先项。

---

## 6. 延迟与同步

| 指标 | 测量方法 | 目标 |
|---|---|---|
| 端到端延迟 | 快速左右晃动，对比真实与虚拟画面 | < 50ms 可接受，< 30ms 良好 |
| 帧率 | Bridge「Pose 频率」 | ≥ 60Hz（DS80 标称最高 200Hz） |
| 抖动 | 静止时观察小数位 | 位置抖动 < 0.5mm |
| 音画同步 | 拍手/打板 | 由 UE 的 genlock / 时间码解决，不靠跟踪链路 |

---

## 7. 多机位

- 每个 Bridge 实例：不同 Free-D 端口 + 不同 Camera ID。
- 每个实例需要独立的 DS80（C 封装一次只管理一台）。
- UE 端每个 Camera ID 对应一个 Subject。

## 9. 出问题时的排查顺序

1. **Bridge 有没有数据**：`pose_monitor.py` → 有包？
2. **SDK 有没有设备**：`SelfTest --device` → 连接结果？
3. **厂商工具能不能跑**：`all_stream.exe` → 有图像/pose？
4. **UE 有没有 Subject**：Live Link 面板 → `Camera 0`？
5. **相机有没有动**：LiveLinkController 的 Subject 选对没有？
6. **方向对不对**：按第 2 节逐轴核对，用「反向」校正。

从下往上查，永远先确认“数据在哪一层断了”。
