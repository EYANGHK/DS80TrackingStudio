# 原点与 UE Lens File 校准

主界面左侧 **项目校准 → 定位原点 / UE Lens File** 打开管理窗口。
原点文件（`.ds80origin.json`）、镜头项目参数（`.ds80lens.json`）和 UE 的 Lens File（`.uasset`）分别保存。
相机、镜头、UE 版本、焦距、对焦距离、有效传感器宽高、画面分辨率都可按项目修改，不绑定任何机型。

## 1. 定位原点

1. 固定 DS80，连接并等待置信度正常。坐标轴和安装补偿应先确认。
2. 将摄像机摆在真实场景参考点，填写原点名称、目标 X/Y/Z（米）及航向（度）。坐标为 **X 右 / Y 前 / Z 上**，不是 UE 的轴顺序。
3. 保持“姿态全部归零”关闭，表示只对齐航向，保留重力方向与俯仰/横滚；开启则以当前完整姿态对齐坐标系。
4. 点“以当前姿态定位”。主界面 `R` 快捷键使用同一组目标设置。
5. 点“保存原点文件”。需要恢复时，连接同一数据源后主动加载。

Bridge 负责安装补偿时，先求摄像机光心，再定位原点；UE 负责 Nodal Offset 时，Bridge 输出跟踪器，原点也以跟踪器为参考。若希望 UE 摄像机光心恰好落在场景参考点，应在 UE 对跟踪父节点做最终场景对齐。

无有效数据、低置信度或数据年龄超过 100 ms 时拒绝采集原点。修改设备坐标系、方向校正、安装偏移或补偿归属后，旧原点自动作废，需重新定位。v0.3.0 起原点文件版本为 2；v0.2.x 的文件使用不同的坐标定义与单位，会被拒绝加载，需要重新定位。

**保存原点不等于保存 SLAM 地图。** 当前程序尚未实现地图保存/重定位。设备重启、重新建图或发生重定位跳变后，旧文件中的世界坐标可能失效；不要跨地图直接复用。程序不会在启动时自动套用旧原点。

## 2. 镜头项目与有效画幅

- 新建、加载、保存项目互相独立；点击“应用项目”才写入当前程序配置。
- 焦距/对焦距离描述当前标定采样点，不代表整支变焦镜头已完成标定。
- 传感器宽高填写**当前录制模式的有效画幅**。不要仅按机型名称、标称传感器宽度或输出画面比例推算高度。
- 录制分辨率与 SDI 传输分辨率可能不同；UE Lens File Editor 中的 Media Source / Camera Feed 设置仍需按实际链路配置。
- 示例 `profiles/FX6_24mm.example.ds80lens.json` 仅预填用户提供的 FX6、24–70 GM、24 mm、宽 35.7 mm。有效高度保持 0、画幅确认关闭；分辨率与对焦距离是待核对的示例值，不能直接当标定结果使用。
- 切换项目或相机时加载对应 JSON，修改 UE `/Game/...` 资源路径；脚本遇到已存在的同名 Lens File 会停止，保护已有标定数据。

## 3. 准备 UE Lens File

1. UE 项目启用 **Camera Calibration、Lens Component、Python Editor Script Plugin、Live Link、Live Link FreeD**；插件依赖及名称以当前 UE 版本为准。
2. 按 [UE5 FreeD 集成](02-UE5-FreeD集成.md) 设置摄像机跟踪，并配置摄像机的视频输入。
3. 无镜头编码器时，关闭 Live Link Camera Controller 的焦距、对焦等镜头属性更新，仅用 Free-D 驱动跟踪变换。当前 Bridge 的 Free-D Zoom/Focus 字段为 0，不能作为 24 mm 或实际对焦距离使用。
4. Bridge 镜头项目中填写参数、核对画幅并勾选确认。若使用 UE 求解/应用跟踪偏移，勾选“由 UE Lens File 应用 Nodal Offset”。Bridge 保留原安装参数但跳过它们；切回 Bridge 补偿时，也要在 UE 关闭 Nodal Offset，避免重复。
5. 点击“应用并导出 UE 脚本”。脚本内包含当前项目参数，不需要额外 JSON 文件。
6. UE 里选中一个 CineCameraActor，添加一个 Lens Component，然后通过 **Tools → Execute Python Script** 执行导出的 `.py`。
7. 脚本创建新的未标定 Lens File，设置镜头模型/画幅/录制尺寸，并初始化所选相机的 filmback、焦距、手动对焦距离。已有 Lens Component 时会绑定新资源并设置 Nodal Offset 开关；没有该组件则按 Output Log 提示手动添加和绑定。
8. 将 Lens Component 的 FIZ 求值模式、手动 Focus/Zoom 输入设成与本次采样点一致的值。检查 Filmback Override、畸变应用和 Live Link 控制是否互相覆盖，审核后保存关卡。

此脚本是**初始化工具**，不会写入畸变、光心、Nodal Offset 或“已校准”的焦距采样表。初始化成功后必须继续实拍求解。本机无完整 UE 编辑器，已检查 Python 语法与可模拟的资源创建逻辑，UE 5.8 编辑器实际运行仍待现场验证；版本差异会显示 API 错误，不应当作校准完成。

## 4. 在 UE 5.8 实拍求解

打开 Lens File Editor，选择 CineCamera 和实际视频输入，填写实物棋盘格的内角点行列数及方格边长（UE 使用 cm）。确保视频与跟踪时间对齐，先用静态画面检查轴向和焦距。

**畸变、焦距与光心**：采集不同画面位置、角度和距离的清晰棋盘格图像，覆盖中心和边缘；使用 Lens Distortion / Intrinsics 求解，检查重投影误差和叠加对齐，再保存 Lens File。初始标称焦距只用作求解初值。

**跟踪偏移 / Nodal Offset**：需要有效相机跟踪与已知棋盘格/场景点关系。当前只有一个 DS80，不能假定棋盘格也被跟踪；不要直接勾选 “Is Calibrator Tracked”。先完成畸变/内参，再选择适合固定标定板或已知场景点的 Nodal Offset 工作流。拥有同一坐标系下的标定板跟踪时，才使用官方同时求解的 tracked checkerboard 流程。

完成后检查相机绕镜头附近旋转时，近处和远处参考物是否保持对齐。不要用修改世界原点来掩盖错误的镜头偏移。对变焦镜头，在需要的不同焦距和对焦距离分别采样；重新安装 DS80、换机身或改变画幅后重新验证。

## 5. 本次性能验证（2026-10-22）

- 模拟器：500 Hz 新 Pose，1000 Hz 主机轮询；五秒 Free-D / JSON 回环约 500 Hz，报文和序号检查通过，无回环丢包。
- 实机（S80，2026-10-22）：2000 Hz 目标轮询；启动稳定后观测到新 Pose 499.7 / 499.9 / 494.0 Hz。初始化期间短暂无 Pose 属实测现象。
- 坐标系：v0.3.0 按 xvsdk 文档改为 `X 右 / Y 下 / Z 前`；旧版 C 接口会把位置取反，且默认预设为 `Y 上 / Z 后`，导致摇摄/横滚方向相反。
- 频率来自实际新帧计数，不使用保持帧补成 500；这是当前机器的测量结果，不是 Windows 硬实时保证。
