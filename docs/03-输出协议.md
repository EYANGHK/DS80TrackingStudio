# 03 · 输出协议

Bridge 同时发两路 UDP，互不影响，可单独关闭。

| 端口 | 协议 | 方向 | 用途 |
|---|---|---|---|
| 40000 | Free-D D1 | 二进制，29 字节/包 | UE5 内置 Live Link FreeD |
| 40001 | DS80-JSON v1 | UTF-8 JSON，无换行 | 调试 / 自定义插件 / 录制 |

发送策略：收到新 Pose 就发；无新数据时以 10Hz 发送“保持帧”，避免 UE 端超时。
模拟器固定 120Hz 产生新帧，实测输出约 105Hz（受 Windows 调度影响）。

---

## 1. Free-D D1（29 字节）

严格按 Vinten free-d Installation Manual V1.4.4 Appendix A.3.2 / B 实现。

| 偏移 | 长度 | 字段 | 编码 |
|---|---|---|---|
| 0 | 1 | 报文头 | 固定 `0xD1` |
| 1 | 1 | Camera ID | 0–255，对应 UE Subject `Camera N` |
| 2 | 3 | Pan | 24 位有符号，1/32768 °，右为正 |
| 5 | 3 | Tilt | 24 位有符号，1/32768 °，上为正 |
| 8 | 3 | Roll | 24 位有符号，1/32768 °，机后看顺时针为正 |
| 11 | 3 | X | 24 位有符号，1/64 mm，右为正 |
| 14 | 3 | Y | 24 位有符号，1/64 mm，前为正 |
| 17 | 3 | Z | 24 位有符号，1/64 mm，上为正 |
| 20 | 3 | Zoom | 24 位无符号（当前恒 0，DS80 无镜头编码器） |
| 23 | 3 | Focus | 24 位无符号（当前恒 0） |
| 26 | 2 | 保留 | `0x00 0x00` |
| 28 | 1 | 校验和 | `(0x40 − Σ bytes[0..27]) mod 256` |

### 数值范围

| 量 | 量程 | 分辨率 |
|---|---|---|
| Pan / Roll | ±180° | 1/32768° ≈ 0.00003° |
| Tilt | ±90° | 1/32768° |
| X / Y / Z | ±131,072 mm（±131 m） | 1/64 mm = 0.0156 mm |

超量程会被截断（不会溢出翻转），实拍场景远远够用。

### 大端 24 位示例

`Pan = +12.5°` → `12.5 × 32768 = 409600` → `0x064000` → 字节 `06 40 00`。

### 校验示例（静止原点）

```
D1 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 40
```

最后一个字节 `0x40` = `0x40 − 0`。用 `tools/pose_monitor.py` 可实时校验。

## 2. DS80-JSON v1

单包一个 JSON 对象，UTF-8，无换行。约 300 字节，120Hz 时约 36 KB/s。

```json
{
  "v": 1,
  "seq": 12345,
  "t": 1234.567890,
  "valid": true,
  "conf": 0.9723,
  "age": 3.0,
  "x": -0.492, "y": -0.258, "z": 1.320,
  "qw": 0.9804, "qx": -0.0755, "qy": -0.0245, "qz": -0.1804,
  "pan": 21.15, "tilt": 8.00, "roll": 4.36
}
```

| 字段 | 类型 | 单位 | 说明 |
|---|---|---|---|
| `v` | int | — | 协议版本，当前 1 |
| `seq` | int | — | 帧序号，单调递增 |
| `t` | double | 秒 | 发送端时间戳（模拟器为 Unix 秒；设备为内部时钟） |
| `valid` | bool | — | 置信度达标且数据未超时（<1000ms） |
| `conf` | double | 0–1 | SLAM 置信度，0 = 丢失 |
| `age` | double | ms | 距上一次收到新 Pose 的时间 |
| `x/y/z` | double | 米 | Free-D 世界系：X 右 / Y 前 / Z 上 |
| `qw/qx/qy/qz` | double | — | 同一坐标系的姿态四元数 |
| `pan/tilt/roll` | double | 度 | Free-D 角度约定 |

> 位置用**米**（JSON 便于人读），Free-D 用**毫米**。两者数值不同，含义一致。

消费者应：

- 用 `v` 做版本判断；
- `valid == false` 时保持上一帧，不要直接归零（否则 UE 里会“瞬移回原点”）；
- 用 `seq` 丢重复包，用 `age` 判断链路是否卡住。

## 3. 端口与网络

- 默认只发本机 `127.0.0.1`，不经过防火墙。
- 跨机时把 Bridge 的「目标 IP」改成 UE 机器 IP，并在 UE 机器放行 UDP 40000。
- 同一台机器跑多个 Bridge 实例时，用不同的 Free-D 端口和 Camera ID。
- Bridge 不监听任何端口，因此不会和 UE / 其他软件抢端口。

## 4. 为什么用 Free-D 而不是直接写 UE 插件（第一阶段）

| | Free-D（当前） | 自绘 Live Link 插件（第二阶段） |
|---|---|---|
| UE 端代码 | 0 行 | C++ 模块 + 编译 |
| 5.4–5.7 | 内置支持 | 需按版本适配 |
| 跟踪状态 / 置信度 | 无（FreeD 没有该字段） | 可自定义 |
| 坐标系 | 依赖 UE 内置解码器 | 完全可控 |
| 调试 | 任何 FreeD 工具都能看 | 需要 UE |

所以第一阶段用 Free-D 快速打通“能动、能拍”，第二阶段再用 JSON 补状态与质量控制。
